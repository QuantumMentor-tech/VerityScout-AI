# Research Result Change Detection Architecture (Step 48)

## 1. Executive Summary

Step 48 implements an evidence-grounded, deterministic, provenance-preserving research change-detection engine for VerityScout AI. It continuously audits and compares successive observations generated by recurring schedules or manual research tasks against eligible baseline runs.

The system ensures that missing data is never misconstrued as real-world removal, units and currencies are compared deterministically with normalization awareness, and all detected delta events preserve bidirectional provenance linking back to underlying source extractions.

---

## 2. Epistemological and Domain Rules

1. **First-Run Baseline Establishment**:
   - The initial research run establishes the baseline.
   - It is marked as `FIRST_RUN_BASELINE` with reason code `FIRST_RUN_BASELINE_ESTABLISHED`.
   - **Zero false changes** are emitted (no spurious "PRICE_DROP" or "NEW_OFFER" events on first runs).

2. **Run Eligibility and Isolation**:
   - Only runs in `COMPLETED` or `PARTIALLY_COMPLETED` state are eligible as baselines or current observation inputs.
   - `FAILED`, `CANCELLED`, or `RUNNING` executions are strictly excluded.
   - Cross-tenant comparison is rejected at the database RLS and application layers.

3. **Scope and Schedule Compatibility**:
   - Compares query string, task ID, and schedule definition snapshots.
   - If the user materially revised the query or research intent, the comparison is marked `INELIGIBLE_SCOPE` with reason code `QUERY_SCOPE_CHANGED` to prevent invalid diffing.

4. **Multi-Pass Identity Matching**:
   - **Pass 1**: Stable product identifier matching (SKU, MPN, Model ID, case-insensitive).
   - **Pass 2**: Normalized canonical URL matching (stripping tracking query params, leading `www.`, and trailing slashes).
   - **Pass 3**: Cleaned alphanumeric title and seller/domain matching.
   - **Variant Separation**: Product condition (`NEW` vs `REFURBISHED` vs `USED`) prevents collapsing distinct offers into a false change.

5. **Deterministic Attribute Comparison**:
   - **Physical Units**: Values like `1.4 kg` and `1400 g` normalize to identical canonical magnitudes (`1400 g`) and evaluate to `UNCHANGED` with reason `VALUE_EQUIVALENT_AFTER_NORMALIZATION`.
   - **Currency Safety**: Different currencies (`$999` vs `€999`) cannot be compared without authorized conversion. They evaluate to `NOT_COMPARABLE` with reason `CURRENCY_NOT_COMPARABLE`.
   - **Monetary Comparison**: Same currency triggers numeric percentage delta computation and classifies as `PRICE_DROP`, `PRICE_INCREASE`, or `UNCHANGED`.
   - **Stock Status**: Availability state changes classify as `STOCK_STATUS_CHANGE`.
   - **Missing Data Distinction**: If a spec or offer is absent in a current run, it is classified as `NO_LONGER_OBSERVED` with reason `ATTRIBUTE_NO_LONGER_OBSERVED`. The system explicitly avoids claiming verified real-world deletion.

## 3. Database Schema and Persistence

- **Migration `0010_research_result_change_detection.sql`**:
  - `research_comparisons`: Stores parent comparison sessions with unique constraint `(baseline_run_id, current_run_id)`, execution status, reason code, summary counters, and tenant RLS isolation.
  - `change_events`: Augmented with `comparison_id`, `candidate_id`, `baseline_evidence_id`, `reason_code`, `change_status`, `explanation`, and unique `idempotency_key`.

---

## 4. API Endpoints

- `GET /api/schedules/[id]/changes`: Lists historical comparisons and latest detected change events for a schedule.
- `GET /api/research/runs/[runId]/changes`: Retrieves comparison results and delta events for a specific research run.
- `POST /api/research/comparisons`: Explicitly triggers comparison evaluation between runs.

---

## 5. UI Presentation

- `ChangeHistoryList`: React client component with summary metric pills, filter tabs (`Prices`, `Availability`, `Specifications`, `Offers`), visual diff rows, percentage delta badges, and direct links to baseline and current evidence records.
- Integrated into `ScheduleManager` with an expandable `Changes` panel.

## 1. Overview

The `ResearchPlan` data contract defines the validated, provider-independent output generated by the planning subsystem. It is consumed by downstream search execution in Step 33, extraction in Step 34, candidate normalization in Step 37, and deterministic constraint verification in Step 38.

## 2. TypeScript Contracts & Zod Schemas

### 2.1 ResearchPlan Contract
```typescript
export interface ResearchPlan {
  readonly id: string;                              // UUIDv4 plan identifier
  readonly status: 'READY' | 'NEEDS_CLARIFICATION' | 'INVALID';
  readonly intent: NormalizedResearchIntent;
  readonly primaryQuery: string;
  readonly searchQueries: readonly SearchQueryVariant[]; // 2 to 5 bounded queries
  readonly ambiguities: readonly PlanAmbiguity[];
  readonly warnings: readonly PlanWarning[];
  readonly createdAt: string;                       // ISO 8601 UTC
  readonly plannerVersion: string;                  // e.g. "1.0.0"
}
```

### 2.2 NormalizedResearchIntent Contract
```typescript
export interface NormalizedResearchIntent {
  readonly originalQuery: string;                   // Exact raw user text
  readonly normalizedQuery: string;                 // NFKC, whitespace-collapsed
  readonly taskType: TaskType;                      // PRODUCT_RESEARCH, SPEC_VERIFICATION, etc.
  readonly targetEntity: string;                    // Clean extracted product or topic
  readonly extractedCategory?: string;
  readonly constraints: readonly NormalizedConstraint[];
  readonly provenance: 'EXPLICIT_USER' | 'DETERMINISTIC_EXTRACTION' | 'AI_INFERRED';
}
```

### 2.3 NormalizedConstraint Contract
```typescript
export interface NormalizedConstraint {
  readonly id: string;                              // e.g. "c-price-ceiling", "c-spec-color"
  readonly type: 
    | 'PRICE_CEILING'
    | 'PRICE_FLOOR'
    | 'CONDITION'
    | 'BRAND'
    | 'SPECIFICATION'
    | 'EXCLUDED_KEYWORD'
    | 'EXCLUDED_DOMAIN'
    | 'GENERIC';
  readonly priority: 'REQUIRED' | 'PREFERRED' | 'EXCLUDED';
  readonly key: string;                             // e.g. "price", "condition", "color", "domain"
  readonly operator: 'EQ' | 'LTE' | 'GTE' | 'IN' | 'NOT_IN' | 'BETWEEN';
  readonly rawValue: string;                        // Literal extracted token (e.g. "300")
  readonly normalizedValue: string | number | boolean | readonly string[];
  readonly unitOrCurrency?: string;                 // e.g. "USD", "EUR", "mm", "GB"
  readonly provenance: 'EXPLICIT_USER' | 'DETERMINISTIC_EXTRACTION' | 'AI_INFERRED';
}
```

### 2.4 SearchQueryVariant Contract
```typescript
export interface SearchQueryVariant {
  readonly id: string;                              // e.g. "q-primary-1", "q-specification_focused-2"
  readonly query: string;                           // Sanitized search query string
  readonly angle: 
    | 'PRIMARY'
    | 'SPECIFICATION_FOCUSED'
    | 'PRICE_AND_DEALS'
    | 'RETAILER_AGGREGATOR'
    | 'ALTERNATIVE_COMPARISON';
  readonly isPrimary: boolean;                      // true for index 0
  readonly rationale: string;                       // Explanation of search angle
  readonly targetedConstraintKeys: readonly string[]; // Criteria addressed
}
```

### 2.5 PlanAmbiguity & PlanWarning Contracts
```typescript
export interface PlanAmbiguity {
  readonly code: 
    | 'MISSING_CURRENCY'
    | 'AMBIGUOUS_ENTITY'
    | 'CONFLICTING_CONSTRAINTS'
    | 'UNCLEAR_RANGE'
    | 'AMBIGUOUS_UNIT';
  readonly message: string;
  readonly field: string;
  readonly suggestedResolutions?: readonly string[];
}

export interface PlanWarning {
  readonly code: string;
  readonly message: string;
  readonly field?: string;
}
```

## 3. Plan Lifecycle & Downstream Consumer Requirements

| Plan Status | Search Execution Allowed? | Required Action |
| :--- | :--- | :--- |
| **`READY`** | **YES** | Can proceed directly to Step 33 Search Provider dispatch. |
| **`NEEDS_CLARIFICATION`** | **NO** | Render interactive disambiguation prompt (e.g. select USD/EUR). Do not execute search. |
| **`INVALID`** | **NO** | Render error card explaining contradictory constraints (e.g. minPrice > maxPrice). |

---

## 4. Downstream Traceability Mapping
- **Step 33 (Search Adapters):** Consumes `searchQueries` array and executes queries across Tavily / Exa / direct engines.
- **Step 34 (Web Extraction):** Uses `intent.targetEntity` and `constraints` for focused content extraction.
- **Step 38 (Constraint Verification):** Validates evidence claims against `intent.constraints` (operator, value, unit).
- **Step 39 (Match Classification):** Evaluates candidate results against required vs excluded constraints.
